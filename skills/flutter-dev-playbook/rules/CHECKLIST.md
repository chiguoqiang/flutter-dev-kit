# 落地与审计清单

配合 `GUIDE.md` 使用。规则文件是代码：进 Git、随 PR review、定期审计。

## A. 新仓库初始化（对应 GUIDE §6 的 30 分钟 SOP）

- [ ] L2 `AGENTS.md` 已建，≤150 行
- [ ] 每条命令逐条人工跑通（跑不通的已删除）
- [ ] 目录地图 ≤10 行
- [ ] 路由表覆盖最容易踩坑的 ≥2 个区域
- [ ] 红线 ≤5 条且条条可判定
- [ ] 适配薄层三件套已建（`CLAUDE.md` / `.cursor/rules/00-agents.mdc` / `.github/copilot-instructions.md`）
- [ ] 完成一次实测任务并确认 Agent 遵循

## B. 季度健康审计

- [ ] 全部命令仍可跑通
- [ ] 路由表指向的文件全部存在且未大改（变了原因列要同步）
- [ ] 无跨层重复规则（L1 ∩ L2 ∩ L3 = ∅）
- [ ] 无互相冲突的规则
- [ ] 删除了 3 个月未生效且未防住事故的规则
- [ ] 行数预算达标（L1≤50 / L2≤150 / L3≤50）
- [ ] globs / applyTo 与当前目录结构一致
  - [ ] CI 门禁仍生效：`.github/workflows/ci.yml` 存在且最近提交有 CI 运行记录
  - [ ] 架构一致性：`docs/architecture/architecture.md` 与实际 import 关系抽查一致（抽 3 个模块）；架构级变更均有 ADR
## C. 单条规则质量检查（写一条过一条）

- [ ] 指令式而非描述式（"必须…/禁止…"，而非"本目录包含…"）
- [ ] 可验证（能客观判断有没有做到）
- [ ] 放在了最近的层（过了 GUIDE §2 决策树）
- [ ] 不与其他规则重复或冲突
- [ ] 必要时附了一个正例或反例

## D. Agent 不守规则的排查顺序

1. 规则太长被稀释？→ 砍行数 / 关键条前置
2. 措辞太弱？→ 改成 MUST / 禁止，配正例
3. 层级太远？→ 下沉到 L3 或前置到 L2 头部
4. 根本没被加载？→ 检查文件位置 / 工具适配层是否生效
5. 与工具默认习惯冲突？→ 换写法或直接给代码示例
