# Playbook D · 业务逻辑 → 代码 SOP（业务文档 → Model/Service + Test）

> 场景：拿到业务规则（产品口头/PRD/口头描述），先落成 `docs/biz/` 文档，再生成代码。
> 本文件是 `PLAYBOOK-NEW-FEATURE.md` 中**类型 E（业务规则变更）**的详细版。
> 文档怎么写见 `BIZ-DOC-TEMPLATE.md`。

---

## 流程总览

```text
口头/PRD 需求 → ① 整理成 docs/biz/<域>.md（不确定点列出来问人）
  → ② L2 路由表登记 → ③ 发 Agent 生成任务 → ④ 人工 review → ⑤ DoD → ⑥ 提交
```

## ① 文档落位（本流程最重要的 10 分钟）

- 按 `BIZ-DOC-TEMPLATE.md` 写入 `docs/biz/<域名>.md`；已有域追加小节
- 写的过程中把**说不清的点**单独列「待确认」小节，找人拍板后回填——
  **禁止 Agent 替你猜业务规则**；宁可文档晚半天

## ② 路由表登记

根 `AGENTS.md` 路由表加一行：

```markdown
| <域>业务规则（判分/错题/…） | docs/biz/<域名>.md | 规则表、状态机与边界算例 |
```

## ③ 发 Agent 生成任务（Prompt 模板）

```text
请实现「<域名>」业务逻辑，规则见 docs/biz/<域名>.md：

1. 先读 lib/models/AGENTS.md、lib/services/AGENTS.md 与 docs/biz/<域名>.md 全文
2. 代码落位（严格按此判断）：
   - 纯计算/校验/状态迁移 → model（或独立 domain 文件），不 import 任何 IO
   - 涉及网络/本地存储 → service，规则判断调用 model 层实现
   - 页面编排/状态持有 → 对应页面，不写业务规则本身
3. 逐条实现「规则表」R1…Rn，代码注释标注规则 ID（如 // R1: score<60 → 写入错题本）
4. 状态机：用 enum 表达状态；非法迁移按文档处理（抛异常/忽略）
5. 测试（与文档一一对应）：
   - 规则表每行至少 1 个用例，用例名含规则 ID（'R1: 提交不及格写入错题本'）
   - 公式算例逐行转为用例（含全部边界值）
   - 状态机：每个合法迁移 + 至少 1 个非法迁移
6. 完成后 flutter analyze 零 error、flutter test 全绿

约束：不改生成文件；不动 android/ios；不新增依赖；业务规则禁止写在 UI 文件里。
```

## ④ 人工 review 检查清单

- [ ] **规则表逐行有对应测试**（按用例名里的规则 ID 数一遍）
- [ ] 公式的全部边界算例都在测试里（0/空/全对全错/极大值）
- [ ] 状态机无"死状态"、非法迁移行为与文档一致
- [ ] 业务规则没有被写进 page/widget 文件（分层正确）
- [ ] 术语与文档术语表一致（没有同义异名）
- [ ] 代码注释带规则 ID（以后改规则能定位到测试）

## ⑤ DoD

同 `PLAYBOOK-NEW-FEATURE.md` 第 4 步，另加：**验收标准的 Given/When/Then 逐条手动走一遍**。

## ⑥ 提交

`feat(biz): <规则一句话>`；文档与代码同一 PR。

---

## 常见坑（踩过才留）

- 文档留白的地方 Agent 会"合理脑补" → 所有留白进「待确认」
- 规则表没写优先级，两条规则打架 → 按文档优先级实现并加注释
- 口头改规则没回写文档 → 下次生成直接回退；**改规则先改文档**
- 公式没给除零/负数算例 → 上线必崩；模板里已强制
