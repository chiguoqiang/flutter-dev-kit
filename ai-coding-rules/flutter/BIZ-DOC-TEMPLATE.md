# 业务逻辑文档标准模板

> 目的：把"人话需求"变成**Agent 可无歧义实现**的规则说明。规则表/状态机/公式 → service/model 代码 + 测试
> （流程见 `PLAYBOOK-BIZ-LOGIC.md`）。
> 组织方式：一个业务域一个文件，放 `docs/biz/<域名>.md`（如 `docs/biz/quiz.md`）。
> 判断标准：**文档里每一条规则、每一组算例，都能直接对应一条测试用例**；做不到就还没写清楚。

---

## 模板（复制后按节填写，用不到的节删掉）

```markdown
# <域名> 业务逻辑 · <系统名>

## 1. 背景与目标
<两三句：谁、在什么场景、要达成什么>

## 2. 术语表（业务词 → 代码名，防止望文生义）
| 业务术语 | 代码命名 | 说明 |
|---|---|---|
| <错题> | <wrongQuestion> | <判定标准：判分为 0 即错题？还是主观题未通过？> |

## 3. 状态机（有状态流转才写）
| 当前状态 | 事件 | 下一状态 | 副作用 |
|---|---|---|---|
| <idle> | <startPractice> | <practicing> | <记录开始时间> |

- 非法迁移的处理：<抛异常 / 忽略并记日志>（必须写明，不允许留白）

## 4. 规则表（核心：一行规则 = 一条测试）
| ID | 触发条件 | 动作/结果 | 优先级 | 例外 |
|---|---|---|---|---|
| R1 | <练习提交且 score < 60> | <全部错题写入错题本> | 高 | <已存在同题则更新时间> |
| R2 | <…> | <…> | <…> | <…> |

## 5. 计算公式（有数值计算才写）
<正确率 = 正确题数 / 总题数 × 100%，四舍五入取整>

算例（**必须给边界值**，实现方直接当测试数据）:
| 输入 | 期望输出 | 说明 |
|---|---|---|
| 0 题 / 0 题 | <0（防除零）> | 边界：空列表 |
| 3 / 10 | 30 | 常规 |
| 10 / 10 | 100 | 边界：全对 |

## 6. 边界与异常
- 空数据：<空列表如何展示/返回>
- 极值/重复：<同题重复提交、超大数字、负数…>
- 时机冲突：<请求进行中退出页面、两次快速点击…>

## 7. 数据影响
| 操作 | 读 | 写 |
|---|---|---|
| <提交练习> | <Record> | <wrongQuestions、history> |

## 8. 验收标准（Given/When/Then）
- [ ] Given <练习含 2 道错题> When <提交> Then <错题本新增 2 条>
- [ ] Given <…> When <…> Then <…>
```

## 写文档的规则

1. **术语表必填**：同一个词在代码里只能有一个名字；"判定标准"要写到可执行（什么是"错题"）
2. **规则表禁止形容词**："提升体验"❌ → "提交后 500ms 内展示结果动画"✅
3. **公式必须配边界算例**：0、空、全对/全错、极大值——没有算例的公式必然被实现错
4. **状态机必须写非法迁移**：留白 = Agent 自由发挥 = 埋雷
5. 规则变更必须同 PR 改本文档（与 API 文档同一条纪律）
