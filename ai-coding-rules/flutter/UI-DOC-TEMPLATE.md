# UI 规格文档标准模板

> 目的：描述"一个页面长什么样、怎么交互"，让 Agent 能生成页面与交互代码
> （流程见 `PLAYBOOK-UI-PAGE.md`）。
> 组织方式：一页一文件，放 `docs/ui/<页面名>.md`（如 `docs/ui/wrong_questions_page.md`）。
> 有 Figma 链接时本文件仍要写——Figma 提供"长相"，本文件提供"行为与文案"。

---

## 模板（复制后填写，用不到的节删掉）

```markdown
# <页面名> · UI 规格

- 页面文件：lib/pages/<name>_page.dart
- 入口 / 路由：<从哪进入、如何返回、是否可从深链进入>
- Figma：<链接（含 node-id）| 截图路径 | 无（按设计基线自由发挥）>

## 1. 页面目标（一句话）+ 主操作
用户来这页干什么；**主操作按钮放拇指区（屏幕底部 1/3）**

## 2. 结构分区（自上而下）
| 区块 | 内容 | 数据来源 | 空数据时 |
|---|---|---|---|
| <顶部标题栏> | <标题+返回> | 静态 | - |
| <错题列表> | <题目卡片×N> | <wrongQuestionStore> | <插画+文案+去练习 CTA> |

## 3. 四态（每一页都必须定义；Figma 通常只画了 success）
| 状态 | 表现 |
|---|---|
| loading | <骨架屏 / 转圈> |
| empty | <插画 + 一句话 + CTA> |
| error | <文案 + 重试按钮> |
| success | <正常内容> |

## 4. 组件与样式（Figma 有则标注"以 Figma 为准"）
- 列表项：<卡片、左题干右状态角标、点击进入重做>
- 颜色/圆角/字体：**一律走 theme，此表只写语义**（如"主按钮=primary"），禁写色值
- 间距：8pt 网格（4/8/12/16/24/32）
- 点击热区 ≥ 44×44

## 5. 交互事件表（核心：一行 = 一处接线）
| # | 触发 | 行为 | 备注 |
|---|---|---|---|
| I1 | 点列表项 | 跳转 <重做页>，携带 <题目id> | |
| I2 | 下拉 | 刷新列表 | 无刷新则写"无" |
| I3 | 点重试 | 重新请求 | error 态 |

## 6. 文案（用户可见的全部文字，含空态/错误态）
| 位置 | 文案 |
|---|---|
| 标题 | <错题本> |
| 空态 | <还没有错题，去练一组吧> |

## 7. 边界情况
- 长文本：<题干超 2 行截断显示…>
- 数量极多：<分页/懒加载规则>
- 异步竞算：<请求中退出页面、双击防抖>

## 8. 验收标准
- [ ] 四态齐全；事件表逐条可操作；文案与本文档一致
```

## 写文档的规则

1. **四态必填**：设计稿几乎只画 success 态，其余三态不定义 = 上线后白屏/卡死
2. **事件表不写"等交互"**：每个可点元素一行；没有的行为显式写"无"
3. **文案全量列出**：文案进代码前先在这里评审，避免 Agent 自己编
4. 样式只写语义不写色值（色值属于 theme/Figma，重复定义必打架）
5. 无设计稿时，按设计基线执行：一个字体族、≤4 种字号 2 种字重、60/30/10 配色、
   8pt 间距、软阴影、44pt 热区、空态配 CTA
